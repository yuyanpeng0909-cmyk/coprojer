# Coprojer

**把需求讨论、交互原型、开发、独立验证和逐项验收放进一个本地桌面工作空间。**

Coprojer 面向个人开发者与需要工程引导的使用者，基于 Electron、React 和 TypeScript。接入自己的模型服务后，由任务规划、原型前端、开发、测试校验四类角色协作；需求、方案、实际文件修改和验收证据保留在同一个项目中。

![真实番茄钟项目工作台：下一步、交付状态与功能列表](docs/screenshots/pomodoro/02-workbench.png)

**开发更新：2026-09-28。** 新增新手入门、阿里云快速导入、模型榜单推荐与实例推理设置、流量监控、验证条件自动准备，并改进长任务上下文与中断恢复。当前提供源码和本机运行能力。

页面下半部分保留 **2026-09-27 真实「番茄钟助手」续跑教程**，作为既有案例；案例的时间、模型、功能数量与验收结果只对应当时的隔离运行。教程图片为最大化应用截图，可点击查看原图。

> 自动验证通过后仍需使用者亲自试用和验收。支持连接不等于真实账号或所有型号都经过实测；模型用量也不等于供应商账单。

## 快速启动

需要 Node.js **22.12+**、npm，以及有有效凭据的模型连接。当前交付源码与本机运行能力，尚无安装包或云服务发行版。本轮环境为 Windows，其他操作系统没有在本轮实测。

```powershell
git clone https://github.com/yuyanpeng0909-cmyk/coprojer.git
cd coprojer
npm ci
npm run dev
```

Windows 安装依赖后也可双击 `start-dev.cmd`。前端修改会热更新；`npm start` 先构建再启动本地生产模式。

首次使用可从侧栏「新手入门」完成模型与四角色配置，然后按「选择或新建项目 → 描述目标 → 试用原型 → 确认需求 → 审阅方案 → 开发与验证 → 实际试用验收」推进。已有项目从项目库继续，引导可暂停、恢复，并按真实项目进度显示下一步。详见[新手入门指南](docs/ONBOARDING.md)。

## 首次创建与模型配置

### 1. 新建项目

点击「新建项目」或 `Ctrl+N`，填写名称、父目录和目标。窗口检查 Node/npm 与目录；创建使用新子目录，不覆盖同名工程。缺少模型时进入「先连接模型」，项目草稿保留。

下图为 9 月 27 日案例独立展示的创建入口，**未提交新工程**；案例主流程使用已有真实项目的副本。完整新建链路另由隔离 Electron 回归验证。

![最大化应用中的新建项目表单](docs/screenshots/pomodoro/00-create-project.png)

### 2. 接入模型

进入「模型连接 → 新增模型」，选择预设或自定义地址，填写 Base URL、协议、API Key 和实际模型 ID。支持 Chat Completions、Responses、Anthropic Messages；可获取型号列表，也可手填。

阿里云百炼新用户可选择「模型连接 → 阿里云快速导入」：从官方入口注册并获取北京地域普通 Key，粘贴后识别型号；登录百炼控制台授权后扫描实际免费额度，预览并一键装配未配置的助手与智能体。免费模式只接受余额有效且已开启「用完即停」的型号。已有连接、绑定和专属 Skill 保留，详见[快速导入指南](docs/ALIYUN_IMPORT.md)。

- 「测试连接」检查普通回复；「检查开发能力」检查工具往返和结构化结果。探测通过不保证所有工程任务成功。
- 首次保存模型可绑定尚未配置的默认四角色；后续按角色分别分配。
- 「复用连接」沿用地址、协议和密钥，另存具体型号。
- 默认通用助手模型用于问答、技能推荐和配置建议；支持下一次请求单独选择，工程开发与验证使用各自绑定。

![新增模型：服务预设、三类协议、能力检查和模型标识](docs/screenshots/pomodoro/17a-model-setup.png)

![已保存的模型及默认助手设置，服务地址已遮罩](docs/screenshots/pomodoro/17-model-connections.png)

9 月 27 日案例中的开发、独立验证实际使用已配置的 `glm-5.3-flash`。其他型号是工作空间原有配置，不能据此推断其官方供应情况或能力。该案例展示新增表单，没有新增付费账户或替换原密钥。

## 真实项目完整操作流程

以下为 **2026-09-27** 的隔离续跑记录，保留当时事实；并非 9 月 28 日重新运行或从零生成整个番茄钟。历史讨论中的 Tauri 是当时方案，实际程序为 Electron/React。

先复制注册的「番茄钟助手」工程和 Coprojer 资料，再以独立资料目录启动。模型凭据保留在本机加密资料中。本轮提交只包含产品修复、文档和筛选后的截图证据，不上传完整应用资料。

| 起点与结果 | 本轮记录 |
| --- | --- |
| 续跑对象 | 注册工程 `test/番茄钟助手` 的隔离副本 |
| 已有成果 | 需求、圆桌、KIMIK3 原型、规格、部分代码、4 项历史已验收状态 |
| 本次新执行 | 统计功能真实模型开发与独立验证、原生应用测试、验收操作 |
| 当前有效功能 | 9 项；另有 1 条已合并历史记录单独追溯 |
| 结束状态 | 5 项已验收、2 项就绪、2 项方案阶段 |
| 原始资料保护 | 原应用主数据及原工程既有改动哈希保持一致 |

在「项目管理」可搜索、排序、置顶、重命名、归档/恢复，打开目录或继续开发。

![真实项目库与继续开发入口](docs/screenshots/pomodoro/01-project-library.png)

### 1. 查看已有需求与圆桌

打开「需求与功能图」或「需求讨论」。左侧保留讨论和人工反馈，右侧查看功能图、原型与子项目。支持单模型讨论和多模型圆桌，圆桌按提案、交叉评审、主持汇总推进。

需要取舍时出现决策卡：选择建议、输入想法，或「后面再说」交给后续模型研究。决定和未决事项保留，停止及重启后可继续。下图为**已有真实讨论的复查**，没有为截图重跑整场圆桌。

![已有圆桌讨论及功能图](docs/screenshots/pomodoro/03-discussion-map.png)

功能图支持缩放、定位、独立窗口和 SVG/PNG/Markdown/JSON 导出；多端工程可记录子项目目录、接口和职责边界。相关高级交互通过本轮协议夹具与真实 Electron 回归覆盖，见[功能矩阵](docs/FEATURE_CATALOG.md)。

### 2. 试用原型，辨认版本与依据

在「原型设计」查看历史版本、设计反馈和预览，可打开独立窗口。新项目通常先收集设计意见，生成和迭代交互原型；点击「验收此原型」后自动提取 PRD 与候选功能。

![原型面板与历史版本入口](docs/screenshots/pomodoro/04-prototype-panel.png)

![独立最大化窗口中的既有 KIMIK3 原型](docs/screenshots/pomodoro/05-prototype-window.png)

这是既有 HTML 原型，**不是后面实际运行的番茄钟程序**。本轮重新打开已有版本，没有重新生成，也没有宣称最终界面已逐像素对齐。确认基线后，方案与执行固定引用选定原型，新版本不会静默替换旧任务依据。

### 3. 审阅需求与规格

「需求与规格」集中展示 PRD、子项目、模块和功能 Spec。目录支持搜索、定位、键盘操作和滚动同步；「已核对」仅记录阅读进度。确认动作提交需求基线，审阅中内容改变时需刷新重新审阅。

![PRD、功能规格、目录与确认状态](docs/screenshots/pomodoro/06-specification.png)

本例沿用已确认资料。历史技术讨论与实际实现存在差异，因此本页分别标注历史方案、当前代码和运行证据。

### 4. 审阅方案与执行顺序

任务看板按阶段展示功能。可逐项生成、编辑和确认方案，或批量准备方案并只重试失败项。「审阅方案并开始」一次最多选择 8 项，核对任务、验收标准和未完成依赖。

![执行前任务看板](docs/screenshots/pomodoro/07-board-before.png)

![方案与任务阶段总览](docs/screenshots/pomodoro/08-plans-overview.png)

![统计功能方案、任务和依赖](docs/screenshots/pomodoro/08-feature-plan.png)

确认后按依赖**串行**交付。执行顺序可查看、调整和保存；缺失依赖与循环依赖不能直接开工。本轮选择「本地数据统计与复盘」，其余就绪功能仍保留。

### 5. 实际开始开发

在统计功能中点击「开始开发」。开发角色读取固定需求、原型和相关上下文，再执行文件工具及工程命令，记录读写、命令结果与文件修改。

![真实模型正在执行统计功能开发](docs/screenshots/pomodoro/09-development-running.png)

本轮新增统计逻辑与测试、调整统计界面。真实开发启动于 **2026-09-27 23:09:59（北京时间）**，文件变更发生在隔离工程。

### 6. 独立验证与修改证据

独立验证角色读取实际源码、运行检查、逐项提供证据；仅声明「完成」不会通过。失败后最多修复 3 轮，再失败则暂停。步骤预算耗尽会保存进度，支持重启后继续，不无限自动续跑。
