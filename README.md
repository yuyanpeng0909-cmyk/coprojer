# Coprojer

面向个人开发者和新手的工程智能体桌面应用。使用 Electron + React + TypeScript，通过默认的任务规划、原型前端、开发和测试校验团队，把想法逐步变成可运行的本机项目。

## 启动

```powershell
npm run dev
```

也可以双击根目录的 `start-dev.cmd`。开发服务器会打开桌面窗口，修改界面后自动更新。在其他电脑首次使用，需要 Node.js 22.12+，先执行 `npm ci`。

## 专用工程工作台

应用只保留真实工程工作区，已移除演示总览、演示项目、资源库、消息中心、组件实验室和旧笔记界面。

| 页面 | 用途 |
| --- | --- |
| 工作台 | 当前下一步、批量审阅开工、项目交付统计与可搜索的功能清单 |
| 需求与功能图 | 需求 / 功能图 / 原型 / 子项目；圆桌协作、人工反馈、多端范围与独立视窗 |
| 任务看板 | 按工程阶段查看功能及其实现任务 |
| 共享上下文 | 按阶段查看资料、归档恢复、查看任务取材与技能版本 |
| 执行记录 | 查看实际文件操作、命令输出，启动并打开目标项目预览 |
| 模型连接 | 配置自定义服务地址、密钥与模型，测试连接或获取模型列表 |
| 智能体 | 四种角色的模型、职责、工具与技能装配，支持本地技能导入 |
| 外观与偏好 | 亮暗主题、强调色、密度与圆角 |

左侧只有一套导航。项目选择器位于顶部，交付流程与配置入口位于侧栏；工作台中的统计、待办、列表、功能图和看板共用真实工程数据。

`Ctrl+N` 新建项目，`Ctrl+K` 查找工作页面或当前项目中的功能。侧栏可折叠，列表与工作区独立滚动。默认打开上次选择项目的工作台；没有项目时展示创建引导。

## 第一次试用

1. 点击「新建项目」，填写名称、位置和目标。窗口会检查 Node.js/npm 和目录；缺少模型时可直接连接，项目草稿继续保留。
2. 保存首个模型后，四个默认智能体自动绑定，基础技能已预装。「检查开发能力」验证工具往返和 JSON；支持 Chat Completions、Responses、Anthropic Messages。
3. 描述想法后，系统主动征集设计意见并生成原型；试用后点击「验收此原型」，系统自动根据这个版本生成 PRD。审阅后「确认需求并准备方案」，实现方案和开发继续沿用已确认原型。
4. 「审阅方案并开始」选择最多 8 项，检查方案和验收标准后开工。系统按依赖串行开发、独立检查，失败最多自动修复 3 轮。
5. 通过预览实际试用，点击「验收通过并继续」启动已确认队列中的下一项。需求确认、方案确认和逐项最终验收仍由你掌握。

共享上下文按功能、依赖和子项目取材；已确认任务固定基线与原型版本，长资料可分页回查。团队与资料字符预算可在工作台展开设置，技能格式与边界见 [使用说明](docs/ENGINEERING_GUIDE.md)。

详细步骤和本机执行边界见 [第一期使用说明](docs/ENGINEERING_GUIDE.md)，交付范围见 [实施计划](docs/IMPLEMENTATION_PLAN.md)。

详细交互、数据保存与技术边界见 [需求工作区说明](docs/REQUIREMENTS_WORKSPACE.md)。

需求页可切换「圆桌讨论」并选择多个模型：各模型边提案、评审边更新功能图，需要人工取舍时立即弹出决策卡，可选择、输入想法或「后面再说」交给后续模型研究。主持人汇总后等待完整方案审阅。多端产品在「子项目」中明确各端功能、目录和接口，并分别打开功能图或原型窗口。操作与能力边界见 [圆桌与多端项目规划](docs/ROUNDTABLE.md)。

## UI 与本地资料

[UI 1.6](docs/UI_SPEC.md) 固定亮色、中性黑白、紧凑桌面布局，沿用本地 Inter 与 Noto Sans SC 字体。页面标题 16px、正文 12–13px、基本控件圆角 6px。聊天采用左右灰色 / 淡绿气泡和柔和的单层输入区。公共组件已经迁移到 `components/`，不再依赖演示目录。

Windows 开发资料保存在 `%APPDATA%/Coprojer-dev/`。工程资料为 `engineering-v1.json`，密钥使用系统加密后保存，不返回界面。目标目录的 `.coprojer/` 导出功能、完整需求、讨论、上下文与活动 Markdown，以及原型版本 JSON。

原有笔记界面虽已移除，已保存的笔记和文件夹资料不清除；主题与外观设置兼容原有存储键。项目选择单独保存。同一资料目录只启动一个实例，避免同时写入冲突。

## 命令与验证

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 开发模式启动 |
| `npm run typecheck` | TypeScript 检查 |
| `npm run build` | 类型检查并构建到 out/ |
| `npm start` | 构建后启动本地生产模式 |
| `npm test` | 构建、专用工作台、完整工程流程与需求空间回归 |
| `npm run test:engineering` | 构建并验证模型与工程全流程 |
| `npm run test:research` | 构建并验证流式讨论、原型、导图导出与独立窗口 |
| `npm run test:novice` | 构建并验证首次配置、技能、上下文及批量开工与验收续跑 |

测试运行真实 Electron，使用隔离的资料和项目目录，覆盖导航、搜索、表单、偏好和旧资料保留，以及三种模型协议、工具执行、确认节点、文件与命令结果、修复上限、预览和重启恢复。测试服务位于 `scripts/fixtures/`，不进入产品运行路径；真实供应商仍需有效账户连接后实测。

UI 验证覆盖 1280×840、860×600 和明暗主题。聊天、原型、圆桌子项目和决策卡的视觉基线分别保存在 `docs/ui/baseline-v1.3/`、`baseline-v1.4/`、`baseline-v1.5/`、`baseline-v1.6/`。

src/preload/index.ts                  受限桌面桥接
src/renderer/src/App.tsx              桌面窗口框架
src/renderer/src/components/          公共 Tabs、Overlay 和控件样式
src/renderer/src/engineering/          工作台、功能、模型和智能体界面
src/renderer/src/workbench.css        专用工作台布局
src/renderer/src/theme.css            统一设计变量
src/renderer/src/usePreferences.ts    兼容已有资料的外观设置
scripts/smoke.cjs                     专用工作台交互回归
scripts/engineering-smoke.cjs         工程与模型协议全流程回归

当前交付源码开发和本地运行，尚不包含安装包或云端发布。命令在目标工程目录执行，但不具有操作系统级沙箱隔离，具体边界见使用说明。
