# 测试场景

[示例首页](README.md) · [流程讲解](../../docs/examples/pomodoro.md)

先安装示例依赖，再运行 `npm run typecheck`、`npm test` 和 `npm run build`。测试文件是可执行的规则说明，适合对照源码阅读。

## 自动化检查

| 场景 | 关键断言 | 所在测试 |
| --- | --- | --- |
| 初始配置 | 默认专注、短休、长休为 25 / 5 / 15 分钟 | [timer.test.ts](tests/timer.test.ts) |
| 开始与暂停 | 按绝对时间递减；暂停保持剩余时间，继续后恢复计时 | [timer.test.ts](tests/timer.test.ts) |
| 周期转换 | 专注结束进入短休；完成四次专注进入长休 | [timer.test.ts](tests/timer.test.ts) |
| 手动结束与重置 | 按规则切换阶段并返回专注时长 | [timer.test.ts](tests/timer.test.ts) |
| 自定义配置 | 自定义时长与显示格式生效 | [timer.test.ts](tests/timer.test.ts) |
| 系统设置隔离 | 保存普通设置不会改变已经开启的自启状态 | [main.test.ts](tests/main.test.ts) |

计时测试通过传入时间戳完成，不需要真实等待一个完整番茄周期。主进程测试使用模拟接口，验证代码调用行为。

## 桌面试用

在独立资料目录启动应用，依次检查：

1. 开始、暂停、继续与重置，观察计时显示是否符合操作。
2. 修改专注与休息时长，检查设置保存和重启恢复。
3. 检查专注、短休、长休的转换与完成次数。
4. 对照统计界面和历史记录，检查完成与手动结束的记录。
5. 切换主题，再检查托盘菜单、系统通知与退出行为。

系统托盘、后台运行、通知投递和真实时间精度需要实际桌面检查，不能从单元测试结果直接推出。通过 Coprojer 完成项目时，把这些检查记录到对应验收条件后再决定是否接受成果。
