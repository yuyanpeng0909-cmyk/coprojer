# Coprojer 第一期使用说明

默认入口是项目「工作台」，采用 [UI 1.6](UI_SPEC.md) 的专用工程布局。当前版本面向本机 npm/Node 网页工程，首测场景为从零创建个人记账应用。

左侧为唯一主导航：工作台、需求与功能图、任务看板、共享上下文、执行记录；底部为模型连接、智能体、外观与偏好。顶部选择器切换项目；`Ctrl+N` 新建项目，`Ctrl+K` 查找页面或当前工程中的功能。

工作台显示真实功能统计、待办决策、执行窗口和可搜索的功能清单。点击待办或功能行打开对应阶段详情，不向真实工程中填入演示数据。

需求阶段支持圆桌会议和多端子项目规划。参会模型边讨论边更新功能图，遇到人工取舍立即出卡；支持选择、自由输入和「后面再说」交给后续模型研究，答案与未决事项完整保存。卡片跨停止和重启保留。各子项目可分别打开独立视窗，具体操作见 [圆桌与多端项目规划](ROUNDTABLE.md)。此扩展覆盖需求方案和可交互原型，原生移动端与设备构建工具链尚未扩展。

## 试用顺序

1. 打开「模型连接 → 新增模型」。选择预设或填写自定义服务地址、API Key、模型标识。中转站选择它支持的接口类型；通常可先用「OpenAI 兼容」。点击测试连接后保存。获取模型列表失败时仍可手填模型标识。
2. 打开「智能体」。默认提供开发和验证两个角色，可分别选择模型、修改工作要求和工具配置，也可新增角色。基础读取工具始终可用；验证角色需要命令工具才能执行测试，不提供文件修改工具。
3. 点击「新建项目」，创建「个人记账」等新项目，选择父目录并填写目标。应用会创建全新子目录；已有同名目录不会被覆盖。
4. 在「需求与功能图」描述需求，例如“做一个个人记账网页，支持录入收入和支出、显示结余、刷新后保留数据”。回复以流式方式显示，模型调用工具时同步右侧功能图和完整需求文档。点击节点可直接修改范围、需求、验收标准、智能体和前置依赖。
5. 可在讨论中让设计 AI 生成原型，也可独立打开功能图或原型。审阅「需求文档」与全部功能后点击「确认完整需求」保存共享基线，再进入功能方案页生成或手写方案与任务，检查后「确认方案」。未开发功能可通过「继续修订」重新讨论；已开发目标的变更另建功能。
6. 点击「开始开发」。系统调用模型，通过实际文件和命令工具实现，随后启动独立验证会话。执行记录会显示模型步骤、文件操作和命令输出，可以停止。
7. 进入「待验收」后，查看功能详情中的验收项、修改和日志。在项目「执行记录」中使用 `dev` 脚本「启动项目 → 打开预览」，实际试用。确认结果后「验收通过」；发现问题则填写原因「退回修改」，再继续执行。
8. 上一项最终验收后，手动启动下一项。共享上下文会积累已确认需求、开发总结、验证记录及交付结果，也可手动补充规范与公共业务知识。

## 停止、失败和继续

- 单个项目同一时间只运行一项讨论、方案生成或功能执行；设计 AI 有独立通道，可与讨论同时进行。不同功能的代码交付仍串行。
- 首次开发和验证失败后，最多进行 3 轮修复。仍然失败则暂停，代码和记录保留；模型仅声明“完成”或“测试通过”不会直接通过系统检查。
- 独立验证需要真实测试命令成功、源文件在验证期间未变化、每项验收标准有结果与证据。它仍是模型辅助验证，最终业务验收由使用者完成。
- 「停止」取消当前模型请求或工程命令。「停止预览」关闭当前项目由应用启动的预览进程。
- 同一项目的预览端口固定保存，重启预览后保持相同地址，避免浏览器本地存储因地址变化而隔离。端口被其他服务占用时会提示处理，不悄悄换地址。
- 在暂停功能的需求页可以更换开发/验证智能体，点击「保存执行智能体」，再「继续执行」。继续会开启新批次，旧失败记录保留。
- 手工修复可通过「打开工程目录」操作实际代码；可在共享上下文补充处理说明后继续。重启后中断的工作保持暂停，不自动重复执行。
- 模型响应格式错误或连接失败会在工作台提示，并保留执行记录。可修正连接或切换模型再继续。

## 模型与工具的实际边界

连接测试验证普通文本调用。自动开发还需要所选模型及其服务支持工具调用，且能够按要求返回方案与验证结果。相同模型名称经不同中转站提供时，可用能力可能不同，以实际连接和执行结果为准。

三类协议均适配 SSE 流式讨论，保留自定义 Base URL；展示供应商实际返回的文本、思考和工具参数，普通 JSON 响应兼容一次性显示。工具执行后立即更新功能图和需求文档。暂无多模态输入或服务专属参数面板。详细说明见 [需求工作区](REQUIREMENTS_WORKSPACE.md)。

工具包括共享上下文读取、目录浏览、文本文件读写、npm/Node 命令。文件工具检查相对路径与符号链接，禁止越界访问和改写 `.coprojer/`。命令以项目目录为工作目录执行，没有操作系统级沙箱；npm 脚本、Node 程序及依赖安装脚本具有本机用户权限。工具开关控制模型可调用的接口，并不构成操作系统权限隔离。

每个开发/验证会话最多 36 次模型调用，单次模型请求约 150 秒超时，工程命令最多 300 秒。首次使用需本机 Node.js/npm 可用；目标项目应提供 `dev`、`build`、`test` 脚本，预览脚本需接受 `--host` / `--port` 参数（常见 Vite 项目支持）。目标工程不包含安装包或云端发布。

## 数据与记录

- Windows 本地开发资料：`%APPDATA%/Coprojer-dev/engineering-v1.json`。API Key 使用 Electron 系统加密能力保存，不返回给界面；密钥保护不可用时拒绝明文保存。
- 目标工程的 `.coprojer/FEATURES.md`、`CONTEXT.md`、`ACTIVITY.md`、`REQUIREMENTS.md`、`DISCUSSION.md` 与 `PROTOTYPES.json` 是自动导出的本地记录；主数据由应用管理，直接编辑导出文件不会反向导入。已确认需求和验收记录在界面中不可改写，可添加补充说明。
- 共享上下文区分用户确认的资料与智能体总结，标注来源；总结不是无需核对的代码事实。内容较长时，执行智能体可按索引读取完整原文。
- 修改视图保留文件工具及命令造成的文本文件变化，包括新增、修改和删除。目录扫描上限为 600 个文件、8 层深度；大于 400 KB 的文件、二进制、依赖和构建产物不提供完整前后对照。每项目保留最近 1,200 条活动，界面展示最近 150 条，可在导出记录查看更多。
- 旧笔记入口已移除，其本地资料不清除；主题与外观偏好继续保留。自动化测试使用独立资料目录，不把测试模型或测试工程加入你的真实工作台。

## 已验证与待实测

`npm test` 构建应用并运行真实 Electron 测试。新增工程测试使用本地确定性协议服务，覆盖三种接口的工具往返、模型配置与密钥、空目录创建、功能图编辑冲突、三个确认节点、真实源文件和测试、项目预览、本地页面持久化、最多 3 轮修复、停止/继续以及重启恢复。测试页面和模型回复仅存在于 `scripts/fixtures/`，产品不含模拟执行模式。

尚未使用你的真实 DeepSeek、GLM 或中转站账户完成记账工程生成。配置有效连接后，请按以上顺序完成第一次真实供应商试用；本地协议测试通过不代表每个供应商或模型组合已实测。
