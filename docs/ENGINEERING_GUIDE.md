# Coprojer 使用说明

默认入口是项目「工作台」，采用 [UI 1.6](UI_SPEC.md) 的专用工程布局。当前版本面向本机 npm/Node 网页工程，首测场景为从零创建个人记账应用。

左侧为唯一主导航：工作台、需求与功能图、任务看板、共享上下文、执行记录；底部为模型连接、智能体、外观与偏好。顶部选择器切换项目；`Ctrl+N` 新建项目，`Ctrl+K` 查找页面或当前工程中的功能。

工作台首先显示「下一步」：描述想法、填写设计意见、试用并确定原型、审阅原型生成的 PRD、准备方案、审阅开工、试用验收或处理阻塞。下方保留真实功能统计、待办决策、执行窗口和可搜索的功能清单。

需求阶段支持圆桌会议和多端子项目规划。参会模型边讨论边更新功能图，遇到人工取舍立即出卡；支持选择、自由输入和「后面再说」交给后续模型研究，答案与未决事项完整保存。卡片跨停止和重启保留。各子项目可分别打开独立视窗，具体操作见 [圆桌与多端项目规划](ROUNDTABLE.md)。此扩展覆盖需求方案和可交互原型，原生移动端与设备构建工具链尚未扩展。

## 试用顺序

1. 点击「新建项目」，填写项目名称、存放父目录和目标。窗口检查 Node.js 22.12+、npm 和目录可写权限。创建时使用全新子目录；已有同名目录不会被覆盖。
2. 尚未连接模型时，直接点击「先连接模型」，填写服务地址、API Key、接口类型和模型标识。点击「检查开发能力」后保存；项目草稿保留，四个未配置的默认角色自动绑定此模型。获取模型列表失败时仍可手填模型标识。
3. 描述初步想法，例如“做一个个人记账网页”。已有项目目标即可开始，不要求预先准备完整 PRD 或功能清单。系统主动收集界面风格、设备与关键操作等设计意见；提交意见或采用推荐设计后，原型前端智能体自动设计。圆桌讨论仍是可选入口。
4. 试用原型，提出修改意见后系统自动更新。选择满意的版本并点击「验收此原型」；多端项目各界面都验收后，规划角色自动完整读取这些原型并生成 PRD 和候选功能。审阅页面、交互、业务规则与验收标准，选择「确认需求并准备方案」。方案角色继续读取同一原型，说明如何在它的基础上实现业务；成功方案保留，缺失或失败项可重试。
5. 返回工作台点击「审阅方案并开始」，查看各项方案、任务、验收标准与前置依赖，选择最多 8 项（应包含未完成的前置功能）。确认后系统按依赖串行开发和独立校验。方案在审阅期间发生变化时会要求重新审阅。
6. 进入「待验收」后查看验收项与证据，点击「启动并打开预览」实际试用。「验收通过并继续」记录本项人工验收，再启动已确认队列的下一项。发现问题可「退回修改」并继续执行。

需求阶段先确定原型，再生成和审阅 PRD；之后保留方案确认、最终验收。单项生成/编辑方案、单项确认和只验收不续跑的入口继续可用。未开发功能可通过「继续修订」重新讨论；已开发目标的变更另建功能。纯后台或设备子项目不强制界面原型。

## 四角色与技能

| 角色 | 默认技能 | 职责与工具 |
| --- | --- | --- |
| 任务规划 | 需求与任务规划 | 整理范围、依赖、方案；读取资料与工程文件 |
| 原型前端 | 交互原型与交接 | 生成可交互 HTML 原型；读取资料与工程文件 |
| 开发 | 工程实现与检查 | 实现确认方案；读取、写文件与运行 npm/Node |
| 测试校验 | 独立验证 | 读取实际工程并运行检查；不提供写文件工具 |

在「智能体 → 配置」选择模型、职责说明、工具及适用技能。基础读取工具始终可用；需要命令工具的技能在命令未启用时不可装配。取消工具会卸下依赖它的技能。旧资料升级补齐缺少的默认角色，保留自定义角色、模型和工作要求。

工作台「团队与上下文设置」可选择项目的规划、原型角色以及资料预算；各功能继续单独选择开发和验证角色。一次任务只加载当前角色装配的技能，正文合计上限 16000 字符；尚未实现独立的按需技能正文检索器。

「智能体 → 导入本地技能」选择同时包含 `skill.json` 和 `SKILL.md` 的目录。清单需要稳定的 `id`、`name`、`version`、`description`、`roles`、`requiredTools`。可导入的示例见 [本地验收技能](skills/local-verification/skill.json) 和 [技能正文](skills/local-verification/SKILL.md)。

导入会保存内容副本；编辑源目录后需重新导入同一 ID。内置技能不能覆盖，技能文件不能是符号链接，单文件上限 30 KB，正文上限 16000 字符。只接受已注册工具和角色；技能不添加浏览器等新执行能力，也不能扩大工具权限。当前提供内置和本地导入，不提供公开市场或远程自动安装。

## 上下文与版本

- 每次取材优先保留项目目标、当前功能、验收条件、方案、子项目边界和人工决定，然后补充当前功能、依赖功能及公共资料。已归档、被新基线替代或其他子项目的资料不会常规注入；旧任务仍可引用自己固定的基线。
- 原型验收后记录选定版本，PRD 保存来源原型 ID 与需求指纹。自动提取 PRD 和功能清单不会反过来使该原型过期；之后手动修改需求会要求重新审阅设计。确认需求时将原型固定到功能基线，新原型不会静默改变已确认功能的实现依据。
- PRD、方案生成和开发校验必须完整分页读取所绑定的原型；开发在读完前不能写文件或执行命令。验证单独报告原型对照依据，未实际检查视觉时必须说明；自动报告不能替代使用者试用验收。
- 工作台可设置 8000–64000 字符的资料预算，默认 32000。超长必需约束会明确报错，要求拆分功能；不会截掉验收项继续运行。此预算只计算组装资料，不等于模型 token。
- 历史讨论与工具往返分别有字符预算；工具往返只在完整回合之间压缩，保留最新调用与结果。所有协议另有序列化请求总量 160000 字符上限，覆盖技能、工具、资料和对话，超限在发送前报错。
- `read_context` / `read_file` 每页最多 6000 字符，返回 `offset`、`nextOffset`、`version`；后续携带版本读取，原文变化时重新从第一页开始。功能、原型和讨论可按索引检索，摘要不替代原文。
- 「共享上下文」支持归档/恢复工程补充与执行总结，并展示有效状态、修订号。已确认基线、最终验收和项目目标不能归档；已确认基线与验收记录不能直接改写。
- 最近 200 次角色调用保存实际模型、技能版本与内容哈希、注入资料 ID、字符数及未注入数量。页面展示最近 6 次，完整记录保存在本机主数据；这是调用取材记录，不是供应商 token 计费日志。
- 命令输出和活动记录有长度限制，不保证完整日志。需要完整检查证据时让工程检查程序写入项目文件，再分页读取；不要为找回输出而重放有副作用的命令。

## 停止、失败和继续

- 单个项目同一时间只运行一项讨论、方案生成或功能执行；设计 AI 有独立通道，可与讨论同时进行。不同功能的代码交付仍串行。
- 首次开发和验证失败后，最多进行 3 轮修复。仍然失败则暂停，代码和记录保留；模型仅声明“完成”或“测试通过”不会直接通过系统检查。
- 独立验证需要真实测试命令成功、源文件在验证期间未变化、每项验收标准有结果与证据。它仍是模型辅助验证，最终业务验收由使用者完成。
- 「停止」取消当前模型请求或工程命令。「停止预览」关闭当前项目由应用启动的预览进程。
- 同一项目的预览端口固定保存，重启预览后保持相同地址，避免浏览器本地存储因地址变化而隔离。端口被其他服务占用时会提示处理，不悄悄换地址。
- 在暂停功能的需求页可以更换开发/验证智能体，点击「保存执行智能体」，再「继续执行」。继续会开启新批次，旧失败记录保留。
- 手工修复可通过「打开工程目录」操作实际代码；可在共享上下文补充处理说明后继续。重启后中断的工作保持暂停，不自动重复执行。
- 模型响应格式错误或连接失败会在工作台提示，并保留执行记录。可修正连接或切换模型再继续。
- PRD 生成失败或中断保留已确认原型和原文档，可直接重试。重启后中断的 PRD 标为待重试，不重新要求用户验收同一个原型。

## 模型与工具的实际边界

「测试连接」验证普通文本；「检查开发能力」执行无工程副作用的工具调用，再要求模型返回包含工具标记的 JSON。通过检查说明当前连接完成了该探测，不保证任意真实开发任务成功。相同模型名称经不同中转站提供时，可用能力可能不同，以实际连接和执行结果为准。

三类协议均适配 SSE 流式讨论，保留自定义 Base URL；展示供应商实际返回的文本、思考和工具参数，普通 JSON 响应兼容一次性显示。工具执行后立即更新功能图和需求文档。暂无多模态输入或服务专属参数面板。详细说明见 [需求工作区](REQUIREMENTS_WORKSPACE.md)。

工具包括共享上下文读取、目录浏览、文本文件读写、npm/Node 命令。文件工具检查相对路径与符号链接，禁止越界访问和改写 `.coprojer/`。命令以项目目录为工作目录执行，没有操作系统级沙箱；npm 脚本、Node 程序及依赖安装脚本具有本机用户权限。工具开关控制模型可调用的接口，并不构成操作系统权限隔离。

每个开发/验证会话最多 36 次模型调用，规划/原型资料读取最多 12 轮。普通模型请求上限 10 分钟，开发能力探测上限 60 秒；工程命令最多 300 秒。目标项目应提供 `dev`、`build`、`test` 脚本，预览脚本需接受 `--host` / `--port` 参数。目标工程不包含安装包或云端发布。

## 数据与记录

- Windows 本地开发资料：`%APPDATA%/Coprojer-dev/engineering-v1.json`。API Key 使用 Electron 系统加密能力保存，不返回给界面；密钥保护不可用时拒绝明文保存。
- 目标工程的 `.coprojer/FEATURES.md`、`CONTEXT.md`、`ACTIVITY.md`、`REQUIREMENTS.md`、`DISCUSSION.md` 与 `PROTOTYPES.json` 是自动导出的本地记录；主数据由应用管理，直接编辑导出文件不会反向导入。已确认需求和验收记录在界面中不可改写，可添加补充说明。
- 共享上下文区分用户确认的资料与智能体总结，标注来源；总结不是无需核对的代码事实。内容较长时，执行智能体可按索引读取完整原文。
- 修改视图保留文件工具及命令造成的文本文件变化，包括新增、修改和删除。目录扫描上限为 600 个文件、8 层深度；大于 400 KB 的文件、二进制、依赖和构建产物不提供完整前后对照。每项目保留最近 1,200 条活动，界面展示最近 150 条，可在导出记录查看更多。
- 旧笔记入口已移除，其本地资料不清除；主题与外观偏好继续保留。自动化测试使用独立资料目录，不把测试模型或测试工程加入你的真实工作台。

## 已验证与待实测

`npm test` 构建应用并运行真实 Electron 测试。新增工程测试使用本地确定性协议服务，覆盖三种接口的工具往返、模型配置与密钥、空目录创建、功能图编辑冲突、三个确认节点、真实源文件和测试、项目预览、本地页面持久化、最多 3 轮修复、停止/继续以及重启恢复。测试页面和模型回复仅存在于 `scripts/fixtures/`，产品不含模拟执行模式。

`npm run test:novice` 覆盖四角色迁移、首次模型配置保留草稿、能力探测、从一句想法生成并验收原型、自动生成 PRD、读取缺失拒绝与中断重试、旧原型绑定、过期方案拒绝、两项串行交付与验收续跑、上下文归档恢复，以及 1280×840 / 860×600 明暗主题。`scripts/context-skills.cjs` 独立检查长文无损分页、版本变化、千条资料预算、依赖优先、旧基线隔离、PRD 来源与需求变化失效，以及本地技能校验。

尚未使用你的真实 DeepSeek、GLM 或中转站账户完成记账工程生成。配置有效连接后，请按以上顺序完成第一次真实供应商试用；本地协议测试通过不代表每个供应商或模型组合已实测。
