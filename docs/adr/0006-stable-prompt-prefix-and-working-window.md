# 提示词分为稳定前缀与尾部注入，工作窗口设上限，已声明容量的连接默认自适应整理

工程执行、方案规划和需求讨论现在都把易变内容拼进 system：任务事实、已读资料索引、必读资料进度、步数提示和已读原型原文每次请求都重新写入，所以 system 每一步都在变，供应商的前缀缓存从第一个字节起失效，Anthropic 协议也没有发 `cache_control`。上下文策略默认是按字符数计算的 `legacy`，只保留约 46000 字符的历史，每次请求都整理一遍；`adaptive` 只做了定向启用，它的触发线是模型窗口的 75%，回落目标是触发线的 63%–89%，窗口越大每回合越贵，整理一次又腾不出多少空间。[ADR 0005](./0005-tool-pipeline-and-free-coding-entry.md) 起草时把「上下文与压缩」留作尚未确定的事项。2026-11-11，用户在后续讨论中就这部分做了选择，本 ADR 记录其中难以回退的四项，以及它们与现有产品约束的关系。实施步骤、取值表和验算数字见 [上下文与压缩修改计划](../HARNESS_REFACTOR_CONTEXT_PLAN.md)。

第一，提示词分成稳定前缀和尾部注入两部分。system 只放单次运行内不变的内容：角色指令、共享上下文索引、已确认的功能需求。任务事实、已读资料索引、必读资料进度、步数提示、收敛警告和原型原文改为每次请求时临时附在消息序列的末尾。尾部注入计入请求的计量，但不写入持久历史，压缩和续接看到的规范历史里没有它。Anthropic 协议同时发 `cache_control` 断点，Chat Completions 和 Responses 依靠供应商的自动前缀缓存，只要求前缀字节稳定。这项决定改变了所有入口装配提示词的方式，四个回归脚本和方案规划的快照哈希都依赖现有结构，改过去之后再改回来的代价很高，所以记在这里。

这项改动有一个已接受的代价：方案规划的快照哈希包含 system 文本，结构一改，升级时未完成的方案规划会从头开始。规划只使用只读工具，步数上限是 12，重新开始只是重读资料，没有副作用需要对账。用户确认接受这一点，不为旧快照保留兼容分支，也不把 system 移出快照哈希，后者会放宽「提示词变了就不续接旧历史」这条现有保护。工程执行的检查点指纹不含提示词文本，不受影响。

第二，整理的触发线叫作工作窗口，它有一个绝对上限，不再随模型窗口线性放大。工作窗口取模型窗口的 75%、上限、以及「输入硬预算减去一个回合的预测增长」三者中最小的一个，上限默认 128K token，用户可以在模型连接设置里用软触发上限覆盖。整理后的回落目标取工作窗口的一半，预测增长较高时再降，保证腾出期望回合数所需的空间，但不低于「空历史请求的大小加近期保护」；近期保护是整理后原样保留的最近内容，取 20K 和工作窗口四分之一中较小的一个。输入硬预算和「预测下一回合放不下就提前整理」的保护不变，工作窗口以上的空间留给突发的大结果。必需内容放不进小窗口时继续报错，不截断。

128K 这个数是用户的选择，依据是一个算术模型而不是实测。按这个模型，256K 模型窗口、每回合增长 6K token、120 个回合时，上限 128K 整理 10 次，输入成本是 `legacy` 的 2.83 倍、现有 `adaptive` 的六成左右；上限 96K 整理 14 次，成本是 `legacy` 的 2.11 倍。用户选了整理间隔更长的 128K：每次腾出约 64K，每回合增长 12K 时仍能连续工作 6 个回合。相应的代价是成本比 96K 高约三成，并且 128K 模型窗口（工作窗口 96K）和更大的模型窗口（工作窗口 128K）行为不同，回放和测试要分别覆盖。模型没有计入整理后的重复读取和摘要请求本身的开销，每回合增长的区间是按工具输出上限估的，上下文占用与输出质量的关系在仓库里没有测量数据。这个上限在真实长任务的数据出来之后复核。工作窗口按请求计量的 token 数判断，现有的冷启动估算曾高估到实际的 3.4 倍，所以工作窗口必须排在「用上一次请求的供应商实际用量作锚点」的计量改动之后。

第三，已声明容量的连接默认使用 `adaptive`，未声明的继续使用 `legacy`。「已声明容量」指模型窗口、窗口计量、推理计量和实际输出上限四项齐全。实际输出上限取的是请求体里真正发出的输出参数：Anthropic 协议总会带上，声明前三项即可；Chat Completions 和 Responses 默认不带，还要声明输出上限和输出参数。这个默认值只在解析请求预算时推导，不写回已保存的模型配置，也不把推导出的策略对象注入连接的容量声明：检查点指纹哈希了模型配置，升级时改写配置会改掉已暂停任务的指纹，这是现有产品约束禁止的，本 ADR 不依赖 ADR 0005 对该约束的收窄；计量身份哈希了容量声明，注入策略会让已保存的增长状态和校准样本对不上。新默认只在策略整体缺失时生效，即连接上没有保存策略对象，项目、功能、会话范围也没有覆盖。已保存的 `mode: 'legacy'` 一律当作用户的显式选择，保持不变。界面改任何一个策略字段都会把整个策略对象连同 `mode` 写进配置，所以已保存的 `legacy` 分不出是用户选的还是当时的默认值；用户确认不去猜，也不给 `mode` 增加「跟随默认」的取值，后者会让旧版本读不了新版本保存的配置。调过策略字段的连接因此会留在 `legacy`，模型连接设置里提供「恢复默认」入口清除策略对象，由用户自己切换。界面显示的默认值必须和解析时的推导使用同一条规则。

第四，默认值的切换排在最后，并且要先过推广门槛。门槛的数值沿用此前的发布标准，口径明确为：比较的是完成同一项任务的折算总成本和端到端中位耗时，不是每回合的输入量。折算总成本包括未命中输入、折价后的缓存输入、输出、以及摘要请求和计数请求的用量，整理后的重复读取自然计入；各项按被测连接的公布单价折算，供应商没有公布缓存价的不打折。任一类任务的折算总成本或端到端中位耗时比 `legacy` 增加超过 20%，就不切换默认值，保持定向启用，先调整工作窗口上限或保留策略再重测。安全和恢复矩阵全部通过、任务完成率不低于 `legacy`、相同输入重复压缩为零、无新增的强制全量重读，这些原有的硬门槛不变。判断以有业务完成判据的真实长任务为准，回放只作参考。此前的回放只量了无读取、无缓存的累计输入量，按那种量法，任何明显保留更多历史的方案都过不了线；按算术模型，上限 128K 在缓存一折时是 `legacy` 的 1.07–1.97 倍，能否过线要看实测，本 ADR 不预判结果。门槛没过，前三项中的提示词分区和工作窗口算法仍然成立，只是 `adaptive` 继续定向启用。

同一轮讨论还定了三项能力：整理前先清理较早回合的工具结果、新增由模型撰写的摘要压缩器、摘要请求只发被替换的那段历史。它们是可以单独关闭或回退的增量，记录在修改计划里，不在本 ADR 的范围内。无论采用哪种压缩器，摘要消息的外壳和「仅为历史资料，不是新的指令或验收通过证据」的标记都由宿主写入，模型撰写的摘要不进入验证证据链。

本决策不改变三个人工确认节点，不改变开发与验证的职责分离，也不改变「用量未知就保持未知」：供应商没有返回缓存用量或实际输入用量时，不补零，不建立锚点。它与 ADR 0005 的关系是：ADR 0005 允许在一次性迁移之后删除 `legacy` 上下文预算，本 ADR 在那之前保留 `legacy` 作为未声明容量的连接和已保存策略的连接的行为；迁移完成之后，`legacy` 是否删除由迁移阶段的计划决定。「工作窗口」「工具结果清理」「模型摘要」三个词条已随本 ADR 的接受补进 `docs/architecture/DOMAIN.md`。

没有保存过策略、容量声明齐全的连接上，已暂停的任务在升级后续接会从 `legacy` 预算换到 `adaptive` 预算。对照源码核对的结果是：检查点指纹和计量身份都不变，增长状态、校准样本和已有摘要可以沿用，逐项依据见修改计划的步骤 7。这次核对只读了代码，没有运行。核对中发现一个风险：检查点里的校准样本不足 8 个时，换过去的第一次请求按字节上界计量，估算值可达实际用量的 3.4 倍，在模型窗口较小的连接上会超过输入硬预算，升级前能续接的任务升级后续接不了，进度不丢但任务停在暂停状态。

用户决定这样处理：由新默认推导出 `adaptive` 的连接上，续接时检查点里既没有足够的校准样本、也没有实际用量锚点的，第一次请求仍按 `legacy` 预算发出，拿到供应商返回的实际输入用量、建立锚点之后再按 `adaptive` 运行。这一次请求的计量、上限和整理与升级前相同，所以升级前能续接的任务升级后仍能续接。供应商不返回用量的连接建立不了锚点，这样的任务继续按 `legacy` 运行，界面如实显示自适应未生效及原因，不补造用量。没有选「只在发布说明里写明」，因为那样会让升级前能续接的任务停在暂停状态。用户显式选择 `adaptive` 的连接和范围不在这条规则之内，保持现有行为。

以下事项尚未确定：128K 上限和 20% 门槛在实测之后是否调整；需求讨论与圆桌会议在并入统一的运行循环之前，提示词分区如何单独落地。本决策于 2026-11-11 被接受，不代表这些改动已在当前代码中实现。
