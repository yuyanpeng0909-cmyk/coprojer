# 智能体工作要求

更新日期：2026-10-08。

四类基础成员的工作要求统一包含职责与边界、执行步骤、交付与完成标准、协作规则。工作要求会参与实际模型请求；角色类型、工具权限和当前任务阶段仍决定成员能够执行的操作。

| 成员 | 主要职责 | 交付内容与交接 |
| --- | --- | --- |
| 需求与架构 | 澄清业务场景、范围和异常规则；整理验收标准；设计模块、数据与接口；分析依赖和变更影响 | 原型确认前整理目标与设计约束，确认后形成 PRD、架构方案和可执行任务，交给设计、开发与测试 |
| 交互与原型 | 设计页面与导航、完整操作路径、各类状态、窄屏与可访问性；制作沙箱内可操作原型 | 交付原型及页面、组件、数据字段、交互规则和验收关注点，由用户确认后交给开发 |
| 全栈开发 | 在成员分工内实现正式代码、数据存储和接口；处理异常及边界；运行必要检查并修复缺陷 | 交付代码、配置、运行方法、实际检查结果和剩余缺口，交给独立测试；不擅自扩大专项成员的职责 |
| 独立测试 | 将原验收标准映射到检查与证据；独立运行测试；复现缺陷、交回修复并复测 | 逐项报告通过、失败或未验证，区分构建、单测、模拟、真实集成、桌面与持续运行证据，保留用户最终验收 |

完整模板维护在 [agent-instructions.ts](../src/shared/agent-instructions.ts)。共享模板、手动新增成员和无来源的团队推荐成员均使用这些要求；加入项目后仍是独立副本。

## 已有配置的更新

启动更新后的应用时，尚未升级的共享模板和项目成员会执行一次迁移：

- 旧版默认短文案替换为对应角色的完整要求。
- 自定义文案原样保存在“成员分工与专门要求”中，随后追加仅在该分工内适用的角色规范。名称、角色、模型、权限、技能和项目归属不因此变更。
- 追加后会超过 10,000 字符的自定义要求保留原文，不截断内容。
- 为保留任务续接指纹，有检查点的项目所属开发/测试成员，以及可能被其引用的共享开发/测试成员，暂不迁移。处理完检查点后，下次启动再补充。
- 升级有版本标记，重启不会反复追加；之后用户自行缩短或调整要求也会保留。修改共享模板不会持续同步到已经复制的项目成员。

## 查看与编辑

智能体卡片仅展示首段摘要，最多三行。进入“配置”查看和编辑完整要求，长内容在文本框内滚动，弹窗底部保留保存操作。

新增成员默认填入全栈开发要求；切换职责类型时，尚未改动的模板随角色切换。已经编辑的草稿保留，避免覆盖成员的专项分工。

## 本轮检查

- `npm run build`：类型检查与构建通过。
- `node scripts/agent-instructions.cjs`：旧配置迁移、自定义原文保留、项目副本隔离、手动编辑、重启幂等、实际指令组装和暂停检查点保护通过。
- `node scripts/assistant-workspace.cjs`：助手和团队配置的既有定向检查通过。
- `node scripts/agent-instructions-smoke.cjs`：在隔离资料目录中完成真实 Electron 配置读取、新建角色切换、编辑保存、重启恢复，以及 1280 × 840 亮色 / 860 × 600 暗色布局检查。首次显示前定位到 Windows DISPLAY1 非主屏。

交互证据位于 `output/playwright/agent-instructions/evidence.json`。未运行完整回归或付费模型调用；这些检查不证明模型对所有工作要求的遵从率。
