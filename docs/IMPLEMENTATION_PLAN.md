# Coprojer 第一期实施计划

状态：第一期可运行版本已完成，本地回归通过。用户已授权制定计划并开工，结束逐项需求访谈。最新范围以本文及已确认的领域词汇、ADR 为准；UI 遵循 [当前规范](UI_SPEC.md)。真实供应商首测等待使用者在应用中配置有效模型连接。

## 交付目标

在当前 Electron 应用内完成从新项目到功能验收的可运行流程：配置模型与智能体、新建目标项目、讨论需求并维护功能图、确认需求和方案、串行实现、独立验证、失败最多自动修复 3 轮、最终人工验收。首测目标是从零生成本机运行的个人记账网页应用。

## 实施顺序

1. **工程基础与模型配置**：定义共享数据模型；主进程原子保存工程状态，使用系统加密能力保存密钥；提供通用模型新增、编辑、删除、模型列表和连接测试。实现 OpenAI Chat Completions、Responses、Anthropic Messages 三种接口适配，保留自定义地址。
2. **项目与需求工作台**：新建独立项目目录；项目列表、左侧流程、需求对话、可交互功能图与看板；节点和详情共用功能记录，支持直接编辑、范围标记和需求确认。
3. **方案与上下文**：按功能生成方案和任务；支持修改、确认方案；默认开发与验证角色可选择不同模型；共享上下文可查看和编辑，并记录来源。
4. **真实执行与验证**：提供目录浏览、文件读取和修改、npm/Node 命令工具；文件工具限定目标工程，命令在目标工程目录运行，日志持续刷新；保存代码修改前后内容；单项目串行执行；独立验证有真实命令证据；默认最多 3 轮修复，支持停止和继续。
5. **验收与交付**：展示验收项、测试输出、代码变化；人工接受或退回；代码与记录重启保留；提供目标项目启动命令、打开目录和本地预览。
6. **验证**：类型检查、生产构建、原有 Electron 冒烟；使用隔离资料目录和本地协议测试服务验证新增模型、模型工具调用、新建空项目、讨论与节点修改、三个确认节点、代码落盘、真实测试执行、失败修复、恢复和最终验收；检查亮/暗主题及 1280×840、860×600 布局。

## 本次实施采用的具体规则

- 工作台已根据用户后续要求重构为专用工程界面：单一侧栏、真实工程首页、需求与功能图、看板、上下文、执行记录。演示页和旧笔记入口已移除；已存的本地资料保留。公共控件迁移到 components/。
- 模型服务可自定义；DeepSeek、GLM、Leizi API 仅是配置示例，不形成厂商白名单。连接测试结果和工具执行结果分别记录。
- 用户选择一个父目录，新项目创建为其下的全新子目录；不覆盖已有目录。原有工作区数据不会迁移或覆盖。
- 功能图按模块分组；「待讨论/本期/暂缓」与「需求/方案/开发/验证/待验收/完成/阻塞」分别表达范围和工程状态。
- 人工编辑的功能记录具有版本号。模型回复基于旧版本时保留其文本建议，不覆盖用户的新编辑。已确认需求和验收标准不会被执行智能体改写。
- 一个项目同时只运行一项讨论或功能实现；原型设计拥有独立生成通道，可与讨论并行。前置依赖须已验收；当前功能完成验收后手动启动下一项，使第一期队列行为明确可控。后续可以另行设计自动排队。
- 开发和验证使用独立模型会话，接收同一份已确认需求、共享上下文和实际工程内容。验证角色不能修改工程文件；须运行实际检查，并按验收项给出结果。
- 自动修复最多 3 轮，首次开发和验证不计入；超限保留现场。继续会启动新的明确执行批次并保留历史，不伪装之前失败为成功。
- 项目元数据由应用管理并镜像导出为本地 Markdown。密钥不进入工程文件、渲染进程返回数据、上下文或执行日志。
- 文件工具校验实际路径和符号链接，禁止越过项目目录或修改应用管理目录。命令只提供 npm/Node 工程执行；这是本机执行，不宣称具备操作系统级沙箱隔离。
- 首测默认面向 npm/Node 的本地网页工程，模型执行有时间与步数上限；中断时保存实际状态，重启不自动重放未知副作用。
- 本地协议测试服务仅用于测试，不作为产品中的模拟执行模式。真实供应商端到端调用需要用户在应用中配置自己的有效连接；不得将本地测试通过写成真实供应商已验证。

## 完成标准

- 用户可以在界面内添加模型、配置开发/验证角色、新建项目、讨论并编辑功能、确认方案、运行实现、查看真实测试与文件变化、最终验收。
- 软件不会将模型的完成声明直接当作测试通过，也不会将测试通过直接当作人工验收。
- 所有构建与必要测试通过，应用可以启动；文档说明运行方式与实际未验证的外部连接。
