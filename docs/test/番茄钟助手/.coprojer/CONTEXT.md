# 工程共享上下文

## 项目目标

一、需要解决的核心问题
在日常学习、办公、自主精进的场景中，个人普遍存在专注力不足、时间碎片化、工作休息节奏混乱、效率无法量化的问题，现有工具存在诸多短板，具体可分为四大核心痛点：
1. 专注力涣散，无标准化工作节奏
多数人自主工作时，缺乏固定的专注节律，容易频繁刷手机、走神、拖延，出现“久坐摸鱼、短时慌乱”的状态。没有强制且人性化的专注计时约束，无法形成「高强度专注+短时休息」的科学工作模式，导致任务推进缓慢，极易出现拖延堆积的情况。
2. 工作休息节奏混乱，身心消耗失衡
传统计时工具仅具备简单计时功能，无法区分工作时段、短休息时段、长休息时段。用户常出现两种极端：要么持续高强度工作不休息，导致身心疲惫、注意力透支；要么休息无节制，短暂放松演变为长时间摆烂，无法形成循环、规律的作息节奏。
3. 效率数据无记录，成长无反馈、无复盘
日常专注时长、完成番茄数量、高频专注时段等核心数据无法自动统计，用户无法直观看到每日、每周、每月的学习工作效率。缺乏数据复盘依据，难以发现自身效率短板，无法针对性调整作息和工作计划，长期时间投入无量化、无反馈，很难形成持续自律的习惯。
4. 通用工具冗余复杂，个人使用成本高
市面上多数番茄钟软件搭载团队协作、付费会员、广告推送、复杂任务分类等冗余功能，界面繁杂、占用资源高。个人轻量化使用场景下，无需多余功能，繁杂的设计反而分散注意力，同时部分工具强制联网、隐私收集过多，使用体验差、轻量化不足。
二、希望交付的软件成果
本次交付一款轻量化、无广告、纯个人使用、可数据复盘的桌面端个人番茄钟助手，主打简洁高效、专注节律管理，适配学生、职场个人用户的日常自律场景，无需复杂操作，开箱即用，核心围绕「计时管控、节奏循环、数据统计、个性化设置」四大核心能力搭建，具体交付标准与功能如下：
1. 软件基础属性
- 运行形态：桌面端轻量化客户端（Windows/macOS 通用），绿色免安装、启动快速，后台低资源占用，不卡顿、不弹窗。
- 产品定位：纯个人自律工具，无广告、无付费项、无社交协作、无隐私过度收集，所有数据本地存储，保障用户隐私安全。
- 操作门槛：极简交互，零基础上手，无需学习成本，一键启动、暂停、重置番茄计时。
2. 核心功能交付清单
（1）标准化番茄计时核心功能
支持经典番茄工作法逻辑：默认 25分钟专注工作 + 5分钟短休息，每完成4个番茄周期，自动触发15-20分钟长休息。支持自定义时长配置，用户可自由调整工作时长、短休息时长、长休息时长，适配学习、刷题、办公、阅读等不同场景需求。同时提供计时暂停、重置、手动结束当前周期功能，应对突发情况。
（2）智能提醒与状态提示
各周期切换时提供桌面弹窗提醒+音效提醒，清晰告知用户「专注开始」「休息开始」「本轮番茄完成」。专注时段可开启「免打扰模式」，屏蔽多余弹窗干扰，帮助用户沉浸式投入工作；休息时段友好提示放松，避免过度劳累。
（3）本地数据统计与复盘
自动记录用户所有番茄数据，本地存储不丢失，支持多维度数据可视化统计：每日完成番茄个数、当日总专注时长、每周/每月专注数据汇总、历史专注记录查询。简洁数据面板展示核心数据，让用户直观看到自身效率变化，支持手动清空历史数据，方便周期复盘重置。
（4）个性化自定义设置
支持音效开关、提醒音量调节、界面主题切换（浅色/深色）、长休息周期自定义、开机自启、最小化后台运行等个性化功能。用户可根据自身使用习惯定制软件状态，兼顾实用性与舒适度。
（5）极简可视化界面
整体界面简洁干净，无冗余元素，核心计时数字醒目清晰，状态区分明确（专注中/短休息/长休息），布局简约大气，视觉上不产生压迫感，适配长时间后台使用。
3. 交付成果完整内容
- 可直接运行的番茄钟助手客户端安装包/绿色运行程序；
- 完整软件使用说明文档（功能介绍、操作步骤、自定义设置教程）；
- 软件核心逻辑说明、后续可迭代拓展接口说明。
4. 交付预期效果
交付后的软件可完全解决个人专注力差、作息节奏混乱、效率无法量化的问题，帮助用户建立科学的专注工作节律，轻量化、无干扰的使用体验适配日常长期自律场景，通过数据复盘助力用户持续优化时间管理习惯，大幅提升学习、办公效率。

## 1. 产品定位与目标
- 纯个人桌面番茄钟工具：轻量、无广告、无账号、无联网依赖、数据全本地。
- 对应四大痛点：专注无节奏（计时状态机）、工作休息失衡（强制循环）、效率无反馈（本地统计）、通用工具冗余（功能极简）。
- 平台：Windows / macOS，绿色免安装优先（macOS 为拖入即用 .app，语义差异写入交付文档），启动快、后台低占用。
- 轻量硬指标已随 Tauri 定案成为可兑现承诺（见第 6 节）。

## 2. 用户与场景
- 用户：学生、职场个人用户（无协作诉求）。
- 典型场景：开机自启进入托盘常驻 → 一键开始专注 → 25 分钟后提醒休息 → 循环 4 次进入长休息 → 中途被打断则手动结束（时间仍留痕）→ 日终查看当日/周/月统计 → 周期复盘后清空数据重来；关闭窗口不退出，托盘继续计时。

## 3. 业务规则（计时状态机）
- 默认节奏：专注 25min → 短休 5min；每完成 4 个番茄 → 长休 15min；长休结束计数归 1。
- 暂停：保留剩余时间，继续后接着走。
- 重置：回到当前周期起点，**不清空**当日已完成番茄计数（草稿默认值，随整体确认生效）。
- 手动结束（已定案）：当前专注周期记为「中断」——不计入完成番茄数；已实际专注的分钟数计入当日专注时长，并生成一条历史记录。
- 统计口径（已定案）：完成番茄数 = 自然走完的专注周期数；当日专注时长 = 完成周期时长之和 + 中断周期已专注时长之和。
- 长休息时长默认 15 分钟，自定义可覆盖。
- 窗口行为：关闭主窗口 = 最小化到托盘，计时继续；退出仅通过托盘菜单显式退出，退出后进程真正结束。
- 开机自启默认关闭；开启后登录自动启动并直接进入托盘（不弹主窗口）。
- 单实例（工程评审草稿默认）：全局仅允许一个实例运行；二次启动唤起已有实例主界面，不产生第二个计时器、不产生双份统计。
- 异常退出对账（工程评审草稿默认）：强杀/断电导致进行中周期未落盘时，下次启动检测残留的进行中状态（周期类型 + 开始时间戳），补记一条中断记录，时长 = min(实际经过分钟, 本周期计划时长)，与手动中断同口径。
- 计时实现约束（Tauri 特有，随定案生效）：计时状态机与剩余时间计算全部在 Rust 侧基于绝对时间戳完成；WebView 前端仅做展示轮询/事件订阅。原因：WebView 中 JS 定时器在窗口最小化/后台时会被系统节流，前端计时必然失准。

## 4. 功能范围
### V1 包含（9 项）
1. 计时核心：25/5 循环 + 4 番茄长休 15min；开始/暂停/继续/重置/手动结束。
2. 自定义时长：工作/短休/长休时长、长休息触发周期，范围限制（工作 1–120、休息 1–60、周期 2–8），下一周期生效，重启保留。
3. 周期提醒：桌面通知 + 音效；音效开关、音量 0–100（应用内增益，不控制系统音量）。
4. 主题：浅色/深色一键切换并记忆。
5. 本地统计：当日番茄数、当日专注时长（含中断时长）、周/月汇总、历史查询；周期结束（含中断/异常补记）即落盘。
6. 清空历史：手动触发 + 二次确认，仅清历史。
7. 免打扰模式：专注时段屏蔽应用内非必要弹窗；周期切换的系统通知与音效保留；开关持久化。
8. 最小化到托盘：关闭窗口后台计时；托盘菜单（显示主界面/开始暂停/退出）。
9. 开机自启：设置内开关（默认关）；开启后登录自动启动进入托盘；关闭即移除启动项。

### V1 明确不做（硬边界）
账号/登录、任何联网同步、广告、社交协作、付费、复杂任务管理/分类、团队功能。工程承诺：不引入任何隐性依赖（分析 SDK、自动更新器、遥测组件均不存在；Tauri 更新器插件不启用）。

### 待定（later，默认 V2）
主题「跟随系统」选项（V1 只做手动浅/深切换）、历史数据导出等扩展。

## 5. 数据与持久化
- 设置数据：时长配置、音效开关/音量、主题、免打扰开关、开机自启开关（存用户数据目录）。
- 历史记录：每条含日期、周期类型、开始时间、时长、是否完成；中断周期同样生成记录（completed=false，时长为已专注分钟数）；异常补记的中断记录带可区分来源字段；字段为后续扩展预留。
- 存储：本地 JSON，Rust 侧原子写入（临时文件 + rename 替换）防损坏。
- 写入时机：每个周期自然结束或手动结束/中断时立即落盘；异常退出不丢失已落盘记录。
- 运行状态检查点（工程评审草稿默认）：开始/暂停/继续等状态变化时，将「当前周期类型 + 开始时间戳 + 已完成番茄计数」写入本地，作为异常退出对账依据。
- 清空：手动 + 二次确认；仅清历史，不影响设置与进行中计时。
- 计时基于绝对时间戳计算，不依赖累加 tick；系统睡眠/唤醒后自动校准，托盘后台精度与前台一致（Rust 侧实现后此保证天然成立）。

## 既有工程知识
项目目标
一、需要解决的核心问题
在日常学习、办公、自主精进的场景中，个人普遍存在专注力不足、时间碎片化、工作休息节奏混乱、效率无法量化的问题，现有工具存在诸多短板，具体可分为四大核心痛点：
1. 专注力涣散，无标准化工作节奏
多数人自主工作时，缺乏固定的专注节律，容易频繁刷手机、走神、拖延，出现“久坐摸鱼、短时慌乱”的状态。没有强制且人性化的专注计时约束，无法形成「高强度专注+短时休息」的科学工作模式，导致任务推进缓慢，极易出现拖延堆积的情况。
2. 工作休息节奏混乱，身心消耗失衡
传统计时工具仅具备简单计时功能，无法区分工作时段、短休息时段、长休息时段。用户常出现两种极端：要么持续高强度工作不休息，导致身心疲惫、注意力透支；要么休息无节制，短暂放松演变为长时间摆烂，无法形成循环、规律的作息节奏。
3. 效率数据无记录，成长无反馈、无复盘
日常专注时长、完成番茄数量、高频专注时段等核心数据无法自动统计，用户无法直观看到每日、每周、每月的学习工作效率。缺乏数据复盘依据，难以发现自身效率短板，无法针对性调整作息和工作计划，长期时间投入无量化、无反馈，很难形成持续自律的习惯。
4. 通用工具冗余复杂，个人使用成本高
市面上多数番茄钟软件搭载团队协作、付费会员、广告推送、复杂任务分类等冗余功能，界面繁杂、占用资源高。个人轻量化使用场景下，无需多余功能，繁杂的设计反而分散注意力，同时部分工具强制联网、隐私收集过多，使用体验差、轻量化不足。
