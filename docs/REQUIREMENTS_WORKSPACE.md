# 需求工作区

需求探索和功能交付分开记录。讨论可以从场景、模块、业务规则或界面开始，不要求每轮都遵循固定问题表，也不要求模型把自然回复包装成 JSON。

## 使用方式

「需求与功能图」有四个子模块：

- **需求**：左侧持续讨论，右侧在功能图与原型间切换。Enter 发送，Shift+Enter 换行；输入法合成时不提交。中间分隔线可拖动，也可聚焦后用方向键调整。
- **功能图**：在完整工作区查看思维导图，拖动画布平移、滚轮缩放，点击功能查看记录，展开节点查看验收条件。右上方可导出 SVG、PNG、Markdown、JSON，使用系统保存对话框选择位置。
- **原型**：查看设计模型生成的交互原型，切换桌面 / 手机宽度、历史版本或导出独立 HTML。原型中的交互数据仅存在当前预览。
- **子项目**：明确各端职责、目录、功能归属与接口约定，为各子项目分别打开功能图和原型窗口。

右侧面板标题栏的分离按钮，或拖动把手，可把当前功能图 / 原型打开为原生独立窗口。两个面板可以分别打开，读取同一个项目并持续同步；关闭独立窗口不会删除记录。

## 讨论与模型切换

需求页支持「单模型」和「圆桌讨论」两种方式。圆桌中多个模型先提案、交叉评审，主持人汇总后等待人工反馈，再按反馈开展下一轮；人工最终确认后才保存共享需求基线。多端子项目规划和独立窗口的具体使用见 [圆桌与多端项目规划](ROUNDTABLE.md)。

对话使用 Markdown 显示。文本、供应商返回的思考、工具参数和工具结果分别呈现；思考与工具详情可折叠，消息记录模型名称、时间与完成状态。模型没有返回思考内容时，不生成或补造“思考过程”。

原型预览顶部显示简洁设计状态栏，完整子页和分离窗口同样可见。实时展示阶段、接收字符与耗时，可停止；15 秒未收到新内容时显示等待提示。首次生成使用轻量占位，有历史版本时保持原型可用。点击「查看过程」打开侧边抽屉，设计要求、实际思考、工具记录和生成源码默认折叠；源码只在主动展开时显示，思考按 Markdown 排版。失败或停止会保留提示、已收到的内容与之前的原型。可在抽屉中选择历史记录；新记录保存原始输出和完成时间，旧记录兼容读取已有原型内容。设计模型目前直接生成 HTML，没有调用工具时不会显示虚构的工具步骤。

模型回复中的开场说明、Markdown 围栏和结尾解释不属于原型文档。保存新版本与预览历史版本共用 `src/shared/prototype.ts` 提取完整 HTML，原始回复仍保留在过程记录里。预览和 HTML 导出排除文档外的说明；不能提取完整文档时显示错误，不能把整段回复当网页兜底渲染。沙箱与网络限制继续生效。

Chat Completions、Responses、Anthropic Messages 均支持 SSE 接收；文本到达后增量显示，工具参数拼接完整且响应结束后才执行。工具完成时立即更新功能图 / 需求文档，不等整个多步对话结束。服务仅返回普通 JSON 时兼容一次性显示，不把它伪装成流式数据。

切换讨论模型后发送完整已保存的对话文本和操作摘要，旧消息不会被最近 16 条的窗口截掉。较早的思考与原始工具详情仍保存于项目记录；协议专属的签名或加密续接数据只用于同一轮工具调用，不跨供应商混用。超出供应商上下文或发生断流时保留资料并明确报错，不静默删除历史。

「需求文档」保存产品目标、用户场景、业务规则、非功能要求、未决问题和备选方案。模型可调用工具更新，也可由使用者编辑；遇到并发编辑时保留用户已保存的最新版本。

## 原型设计

点击「设计原型」，选择设计模型并填写设计要求；也可以直接在讨论中要求模型调用设计工具。设计读取项目目标、功能、需求文档、完整讨论、共享上下文与上一版原型。

设计 AI 有独立生成通道，设计进行时可以继续需求讨论。同一项目同时最多一项设计任务；「停止设计」保留已收到的输出。每次成功生成完整 HTML 后新增一个版本，生成途中继续显示上一版，不用不完整 HTML 替换可用预览。

原型位于带 `allow-scripts`、不带 `allow-same-origin` 的 iframe 中。预览没有桌面桥接，不能读取父窗口或调用工程接口；内容策略禁止网络、嵌套框架、外部依赖和表单提交。原型文件是设计材料，不会自动写入待交付项目的源码。

## 确认完整需求

点击「确认完整需求」审阅需求文档、所有功能与验收标准以及本期 / 暂缓范围，再保存共享基线。确认操作检查当前版本，防止把审阅后发生的新修改误认作已确认内容。

所有本期候选需有需求说明和验收标准；确认后统一进入方案阶段，暂缓功能继续保留。原来的逐功能「确认需求」入口移除。方案确认和最终验收仍以功能为单位，代码开发继续串行。

后续可继续自由讨论。需要调整尚未开发的功能时，点击「继续修订」重新打开需求草稿，之前的方案与任务需重新确认；原始基线保留。已进入开发或已交付的记录不被讨论工具静默改写，变更作为新候选功能提出。

## 数据与实现

应用主资料保持 `engineering-v1.json`，新增字段向后兼容。每个项目同时导出：

| 文件 | 内容 |
| --- | --- |
| `.coprojer/REQUIREMENTS.md` | 完整需求文档草稿 |
| `.coprojer/DISCUSSION.md` | 原始讨论、模型返回的思考、工具与中断记录 |
| `.coprojer/PROTOTYPES.json` | 原型版本与来源 |
| `.coprojer/FEATURES.md` | 功能与交付资料 |
| `.coprojer/CONTEXT.md` | 已确认共享知识与历史基线 |
| `.coprojer/ACTIVITY.md` | 工程活动 |

开发 / 验证模型通过 `read_context` 获取共享基线，还可以从同一工具的索引读取完整原始讨论分页和原型。讨论中的建议不自动覆盖已确认目标。

实现入口是 `src/main/engineering/requirements.ts`、`stream.ts` 与 `src/renderer/src/engineering/RequirementsWorkspace.tsx`、`FeatureMindMap.tsx`、`PrototypePreview.tsx`。前端约 250ms 获取一次共享状态，流式数据约 200ms 持久化一次，结束和停止时再次保存。重启后未完成响应标记为中断，不自动重放。

## 依赖与依据

导图使用 MIT 许可的 [SimpleMindMap](https://github.com/wanglin2/mind-map)，遵循其[构造与事件接口](https://wanglin2.github.io/mind-map-docs/en/api/constructor/constructor-methods.html)和[导出插件](https://wanglin2.github.io/mind-map-docs/en/plugins/doExport.html)。自然回复使用 React Markdown 与 remark-gfm，禁用原始 HTML 注入。

流式适配依据 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[Anthropic streaming](https://platform.claude.com/docs/en/build-with-claude/streaming) 与 [Responses streaming events](https://platform.openai.com/docs/api-reference/responses-streaming)。

`npm run test:research` 使用真实 Electron 和隔离资料目录，验证增量输出、工具往返、历史接续、基线、原型隔离、独立窗口、导出和重启。测试服务是本地协议夹具，真实供应商连接仍需在应用中填写有效配置后试用。
