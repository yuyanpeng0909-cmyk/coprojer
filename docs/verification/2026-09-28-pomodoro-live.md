## 因实测修复的 Coprojer 问题

1. 旧状态中 `results=[]` / 空缺口导致继续验证走错阶段；现在按原标准恢复明确缺口。
2. 多层 npm 命令如 `test:tray:smoke` 被错误拒绝；现在支持多级 `test:*`，仍保留路径、权限和角色约束。
3. 测试写入带源码/构建清单的报告和截图被误认作源码变化；现在区分生成物与配置、范围文档、测试脚本。
4. 工具历史压缩导致验证者遗忘实际命令；现在注入持久台账，诊断收到本轮命令，复验收到准备动作和 nextStep。
5. 普通连接中断丢失已完成验证命令；现在保存并恢复 reviewer 断点，不仅限于预算耗尽。
6. 同一真实执行同时覆盖 application 和 duration 的表达受限；现在保存多种实际证据类型，history 不能通过叠加标签升级。
7. 模型把回调证据写成原生悬停/菜单通过；现在对明确的原生交互标准检查类型及自认未做的矛盾，旧版未完成交付也恢复未验证。既有最终人工验收不被迁移覆盖。
8. 用户界面可能显示模型“全部通过”的矛盾总结或内部 JSON；现在以系统判定和可读的逐项依据展示，并区分实际检查失败与待补条件。真实失败命令直接出现在准备面板顶部，不能被“仍有未验证项”的提示盖住。
9. 恢复回归进一步暴露：修复者仅返回文字、后续验证未执行检查时，会覆盖同版本的已有失败记录。现在保留未解决失败及原时间戳；无关成功命令不能消除它，相关验收项也不转绿。对应检查实际通过或源码变化后的新验证才会替换证据。
