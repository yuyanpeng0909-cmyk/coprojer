# 番茄钟：从需求到验收

[示例源码](../../examples/pomodoro/README.md) · [测试场景](../../examples/pomodoro/TESTING.md) · [使用指南](../USER_GUIDE.md)

番茄钟的功能足够具体，又包含界面、状态、持久化与桌面行为，适合用来理解 Coprojer 如何组织一次开发。你可以先运行现成代码，再在独立项目中按下面的顺序练习。

## 先看完整流程

**目标 → 需求与功能 → 交互原型 → 确认方案 → 开发 → 独立验证 → 亲自验收**

| 阶段 | 要回答的问题 | 应检查的产物 |
| --- | --- | --- |
| 需求 | 做什么、做到什么程度？ | 功能范围与验收条件 |
| 原型 | 使用者如何操作？ | 可以试用的界面和反馈 |
| 方案 | 怎样实现，先做哪一项？ | 方案、依赖和任务顺序 |
| 开发 | 实际改了什么？ | 文件差异与命令输出 |
| 验证 | 哪些规则已经得到证据？ | 测试结果、失败项与检查记录 |
| 验收 | 真实使用是否满足目标？ | 逐项试用和接受或反馈 |

## 1. 把目标写成可检查的需求

可以从这样一个小目标开始：

> 做一个本地番茄钟，支持专注、短休和长休，可以暂停、继续与调整时长，并能查看自己的专注记录。

在需求讨论中明确默认时长、周期切换、手动结束时的记录方式，以及数据保存位置。将这些规则拆成独立功能，并为每项写出可以检查的完成条件。

![需求讨论与功能图](../screenshots/pomodoro/03-discussion-map.png)

## 2. 先试操作，再确认需求

通过原型检查计时、统计和设置页面的入口，试用开始、暂停和调整时长等操作，再提出反馈。确认原型与需求时同时核对实现技术、功能范围和验收标准。

![原型版本与预览](../screenshots/pomodoro/04-prototype-panel.png)

原型是交互讨论材料；实际桌面程序在示例源码中实现。这个示例使用 Electron、React 和 TypeScript，源码和运行说明是复现时的依据。

## 3. 审阅方案并选择一个小功能

先选择计时规则等边界清晰的功能，查看需要修改哪些文件、依赖什么能力，以及如何验证。确认后再开始开发，完成一项再继续后续任务。

源码中，计时逻辑集中在 [timer.ts](../../examples/pomodoro/src/shared/timer.ts)，相应规则可在 [timer.test.ts](../../examples/pomodoro/tests/timer.test.ts) 中阅读。

## 4. 跟踪代码与执行结果

开发过程中查看真实文件修改和命令输出。将需求与差异对应起来：状态机负责计时规则，主进程负责本地文件与系统接口，界面负责展示和操作。

![代码修改对照](../screenshots/pomodoro/12-code-changes.png)

示例可以通过自己的构建脚本独立运行。它不会随 Coprojer 安装包自动启动，运行方法见[示例说明](../../examples/pomodoro/README.md#运行)。

## 5. 用测试验证明确的规则

运行类型检查、单元测试和构建，再检查独立验证给出的证据。测试失败时保留失败条件，修复后重新执行；缺少桌面观察时补充相应检查。

![验收条件与验证证据](../screenshots/pomodoro/11-acceptance-evidence.png)

[测试场景](../../examples/pomodoro/TESTING.md)列出了代码测试覆盖的规则与需要实际试用的部分。可以尝试修改一条计时规则，观察测试如何帮助识别影响。

## 6. 启动程序并亲自验收

按示例说明在独立资料目录启动桌面程序。检查计时、暂停、阶段转换、设置保存和统计记录；涉及托盘和系统通知时，在实际 Windows 桌面操作后再记录结果。

![番茄钟实际运行界面](../screenshots/pomodoro/13-pomodoro-timer.png)

回到 Coprojer，逐项记录试用结果。满足条件后接受成果；发现问题则描述具体操作、期望与实际表现，让后续修改有清晰依据。

![功能验收与项目进度](../screenshots/pomodoro/22-acceptance-complete.png)

## Coprojer 内部如何推进

需求和方案确认后，工程服务按当前功能组织模型调用。模型请求读写文件或执行命令时，由主进程工具实际执行并返回结果；开发完成后进入独立验证，再由使用者决定是否验收。

| 阅读入口 | 作用 |
| --- | --- |
| [共享工程类型](../../src/shared/engineering.ts) | 定义项目、功能、角色与阶段记录 |
| [工程服务](../../src/main/engineering/service.ts) | 组织讨论、开发、验证与恢复流程 |
| [文件与命令工具](../../src/main/engineering/files.ts) | 执行项目文件和命令操作 |
| [资料存储](../../src/main/engineering/store.ts) | 持久化工程状态与导出记录 |

阅读时可以用番茄钟的一条计时需求作主线，跟随它对应的方案、文件修改、测试结果和验收记录。

## 阅读与复现说明

示例代码可以直接运行；截图展示的是已有工程的操作过程。仓库不分发私人应用资料，克隆源码不会自动恢复截图中的讨论、模型绑定、原型和功能卡。

需要查看原始测试条件与结果时，阅读[案例验证记录](../verification/2026-09-27-pomodoro-walkthrough.md)。这些记录用于追溯对应运行，自己的改动仍按当前代码重新检查。
