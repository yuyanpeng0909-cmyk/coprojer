# 请求反馈、项目团队与模型连接整理

日期：2026-10-08。沿用 UI 1.6 的中性色、组件尺寸、明暗主题与减少动态效果设置。

## 不同场景的加载反馈

| 场景 | 采用的方案 | 进度来源 |
| --- | --- | --- |
| 保存模型、成员、偏好、创建项目、复制团队、删除连接 | 转圈与当前操作名称；短请求延迟 180ms 显示，减少闪烁 | 实际 IPC 请求的开始与结束 |
| 获取模型列表、测试连接、检查开发能力 | 对应按钮转圈并改变动作文字；等待时显示耗时 | 各操作独立标识，不借用其他按钮的 busy 状态 |
| 技能推荐、模型推荐、团队推荐、技能下载 | 转圈、操作名称和耗时；完成后展示完整结果 | 等待真实返回；不将未知耗时换算成百分比，不流出中间 JSON |
| 通用助手、需求讨论、圆桌讨论 | 首字前等待提示，收到文本后逐步显示；保留现有停止与错误恢复入口 | 模型实际增量文本 |
| 原型生成 | 保留现有真实阶段、思考/内容流式与源码字符量；等待图标统一转动 | 现有设计活动与流式消息状态 |
| 批量生成方案 | 已处理数 / 总数，同时注明失败数 | 每个任务实际结束后累加；失败也算已处理，不代表成功 |
| 工程执行与独立验证 | 保留当前阶段、实际执行日志和任务状态；长任务使用停止入口 | 已有后台活动与验证状态，不编造总百分比 |
| 流量查询、初次读取入门状态 | 区域内转圈；保留原有失败提示 | 实际读取状态；后台轮询与草稿自动保存保持安静 |
| 目录选择、导出、打开独立窗口 | 操作名称与转圈 | 原生操作 Promise 的生命周期 |

工具栏和弹窗中提供统一请求提示，覆盖较少使用的保存、导出和管理动作。指示只包含动作名称、数量和耗时，不包含请求内容或密钥。系统开启减少动态效果时停止旋转，保留文字。

按本次用户要求，加载反馈不运行专项验证；编译成功不代表加载行为经过交互验收。

## 团队组织

- 全局“智能体”只展示共享模板；项目侧栏增加“项目团队”。
- 默认四类：需求与架构、交互与原型、全栈开发、独立测试。原型成员生成交互原型，正式前后端由开发成员实现；现有执行工具和技术栈约束不因名称改变而扩大。
- 新项目复制默认模板的模型、工作要求、已装配技能、启用状态和技能资源。项目副本独立保存，编辑共享模板不改变这些副本。
- 旧项目保留现有绑定，项目团队页明确展示共享引用，并提供“复制为项目团队”。已完成的功能和历史运行记录保留原始成员信息。
- 当前团队与未分配的历史成员分开；历史成员默认收起，可主动展开，不删除已有成员或技能。
- 团队推荐应用时优先复用同项目、同来源的已有实例，避免反复应用共享模板生成多余卡片。

## 删除有引用的模型

删除入口先列出当前引用：共享/项目成员、默认助手、助手会话选择、项目讨论与原型、圆桌下次使用的配置及未完成功能的指定模型。

有引用时选择另一条已保存连接，点击“迁移绑定并删除”。同地址、协议和型号的连接仅作为候选默认选项，仍需明确点击；同名不触发自动合并，连接编号用于区分账户或密钥不同的记录。

迁移与删除共同保存，保存失败则回滚相关内存字段。历史聊天、运行记录、模型用量和已完成任务的原始归属不改写。相关项目或助手正在执行时暂停删除；有待接续检查点的功能需先在功能中处理接续/模型切换，避免破坏恢复现场。

## 定向检查入口

- `npm run build`：编译及类型检查。
- `node scripts/team-model-management.cjs`：成员与技能资源隔离、旧团队重复转换、模型引用迁移、运行保护、保存失败回滚和重启恢复。
- `node scripts/assistant-workspace.cjs`：现有助手/团队流程，专属技能断言更新为复制后的实例隔离。
- `node scripts/team-model-management-smoke.cjs`：隔离资料目录中的真实 Electron 团队与删除操作；1280 × 840 / 860 × 600 布局及暗色。证据写入 `output/playwright/team-model-management/`，不测试加载反馈。
